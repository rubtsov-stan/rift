Diff huge text files under a hard memory limit.

Rift diffs large text files under a heap limit you set on the command line, --mem. It writes a unified diff that patch applies to the first file to get the second, and a terminal view lets you jump through the differences before the whole diff is done.

What it does

Four ways to run Rift. Every output on this page ran on files made by rift-gen --seed 7, and each box says where it shows selected lines of a longer output.

Plain diff and --summary unified diff, then the counts

rift a b writes a unified diff that patch applies to the first file to get the second. --summary counts first, so you know how much differs before you write a diff.

{{ m::term(name="land-diff", kind="diff", title="the first hunk of " ~ hunks, caption="One hunk of the full diff. Timestamps dropped, lines cut at 70 columns.") }} {{ m::term(name="land-summary", kind="summary", title="the counts of --summary", caption="Six of the summary's " ~ nsum ~ " lines.") }}

Guide: plain diff, --summary.

Key mode rows compared by key, not by position

An export written in a different row order diffs by content, not by position. --key takes a CSV column, an NDJSON field or a pg_dump COPY column, and lists the keys that were added (+), removed (-) or changed (~), with the line of the record in each file.

{{ m::term(name="land-key", kind="keys", title="rift --key csv:id", caption="Two lines of each kind, then the number of keys of each kind in all. A 32 MiB CSV pair, same keys, shuffled rows.") }}

Guide: key mode. Use case: compare CSV files by key.

Git rift as the diff driver

Git calls any file over 512 MiB binary and prints no diff. Name the large files in .gitattributes and git runs rift git-diff for them, with git's own headers. Not in v0.2.0: it is on main and planned for 0.3, so build from source to use it.

{{ m::term(name="git-driver", kind="diff", title="git diff on a 640 MiB dump", caption="A scratch repository with the dump committed and then changed. The first 10 lines of the output, cut at 90 columns.") }}

Guide: git integration. Use case: git says "Binary files differ".

MCP a diff an MCP client can query

rift-mcp lets an MCP client, such as an editor or a chat app, ask about the diff of two huge files without loading them. It has three tools, summary, hunks_at and next_difference, and every answer has a size limit.

{{ m::term(name="mcp-summary", title="rift-mcp, one tools/call", caption="Captured over standard input and output after the initialize handshake. The call is shown without its jsonrpc and id fields. The answer is cut: its text copy, the byte counts and all but two of the first 20 ranges are left out. rift-mcp builds its diff with a 64 MiB budget unless the call sets mem, so the counts differ from the CLI's.") }}

Guide: MCP server.

What is guaranteed

  • The output is a correct edit script: applied to the first file it gives exactly the second, byte for byte.
  • A line counts as unchanged only after its bytes are compared. Hashes only propose matches.
  • The heap stays at or under --mem. Files are read with pread into fixed buffers, never mmap.
  • A region Rift could not refine within the budget is marked approximate in every output.

What is not

  • The diff is not minimal.
  • A moved block shows in the unified diff as a deletion and an insertion. --summary, --stats and the terminal view list moved blocks, and detection does not find every block.
  • Windows is not supported.
