The data is generated by `rift-gen` with seed 7, profile `sql`, with a mutation starting at about one line in a thousand (`--change-ratio 0.001`, the default). Rift runs at `--mem 256M`. Peak memory is the resident set. Peak heap is Rift's own counter, the part `--mem` limits.

The largest pair measured so far is 50 GiB, read from a SATA SSD. No pair above that has been run.

## Apple M1, 1 GiB and 10 GiB

- **Hardware:** Apple M1, 16 GB RAM, internal SSD.
- **System:** macOS, warm page cache.
- **Date:** not recorded in the README; the table entered the repository on 2026-11-05.
- **Commands:** `bench/run.sh` prints the full results with the commands and seeds. `bench/data.sh` regenerates the data.
- **Source:** the Benchmarks section of `README.md` at the `v0.1.0` tag. The README no longer carries it.

{{ benchtable(name="mac") }}

`git diff` has no 1 GiB row: it treats files over 512 MiB as binary and prints no diff. On the 1 GiB pair Rift's heap peaked at 83.5 MiB, and on the 10 GiB pair at 94.1 MiB.

## Intel Core i5-10600, 256 MiB to 2 GiB

- **Hardware:** Intel Core i5-10600 (6 cores, 12 threads), 16 GB RAM, bare metal.
- **System:** Ubuntu 26.04.1 LTS, Linux 7.0.0-43, CPU governor `powersave` (intel_pstate). Files in tmpfs, so the run measures CPU, memory and the algorithm, not the disk.
- **Date:** 2026-11-14.
- **Version:** Rift at commit `94bdbb1` on main, built with rustc 1.99.1.
- **Command:** `bench/linux-safe.sh --suite standard --reps 5 --ref main`. The runs were `rift --stats --mem 256M a b`, `rift --summary --mem 256M a b`, `diff a b` and `git diff --no-index a b`, plus one run each at `--mem 64M` and `--mem 1G` for the memory rows. Each other time is the median of five runs; the spread of every Rift row is under 0.03 s.
- **Source:** `bench/results/linux-intel-core-i5-10600-2026-11-14/report.md` and `results.json`, in the same directory.

{{ benchtable(name="linux") }}

GNU `diff` was capped at 3 GiB of memory, and the cap killed it on the 1 GiB pair. `git diff --no-index` took 42.55 to 43.77 s on that pair and printed no diff: it treats the files as binary, and its output was 201 bytes.

The two extra rows for each size show what `--mem` does. On the 1 GiB pair, `--mem 64M` took a heap of 19.0 MiB and `--mem 1G` took 328.5 MiB. A larger budget is not always faster; see [Memory](@/guide/memory.md). The report also has the CSV pairs and the thread scaling: `rift --summary` on the 1 GiB SQL pair took 1.04 s on one CPU, 0.62 s on two, 0.47 s on four and 0.46 s on all twelve.

The previous run, on 2026-11-06 with Rift at `v0.1.0`, is in `bench/results/linux-intel-core-i5-10600-2026-11-06/`.

## Intel Core i5-10600, 50 GiB pair on a SATA SSD

This run is disk-bound: the pair is 100 GiB against 16 GB of RAM, so almost every byte comes from the SSD, and the time to read both files once sets the floor.

- **Hardware:** the same machine; the pair on a Samsung SSD 860 (SATA), `/dev/sda2`, an ext2/3/4 file system (`stat` does not tell them apart).
- **System:** as above, governor `powersave` (intel_pstate).
- **Cache:** not dropped; the script runs without root. The pair was written just before the first read, so the last pages of B may have been in the page cache. A and B together are 6.7 times the RAM.
- **Date and version:** 2026-11-14, Rift at `94bdbb1`.
- **Data and command:** `rift-gen --seed 7 --size 50G --profile sql --change-ratio 0.001`, A and B 50 GiB each. `bench/linux-safe.sh --suite standard --reps 5 --ref main --disk-dir DIR`; the disk runs are one run each, at idle I/O priority (`ionice -c3`), with a 1 GiB memory cap.
- **Source:** `bench/results/linux-intel-core-i5-10600-2026-11-14/report.md` and `results.json`.

| Run | Time | Read rate of A and B | Peak heap |
|---|---|---|---|
| `cat a b \| wc -c` (the disk's rate) | 218.7 s | 491 MB/s | |
| `rift --summary --mem 256M` | 299.8 s | 358 MB/s | 69.8 MiB |
| `rift --stats --mem 256M`, full diff of 1.2 GiB | 456.8 s | 235 MB/s | 80.6 MiB |

`--summary` takes 1.37 times as long as reading the files once, and the full diff 2.09 times. Where the extra time of the full diff goes is open: [#50](https://github.com/rubtsov-stan/rift/issues/50). The heap stayed under 81 MiB on a pair of 100 GiB.

## What these numbers do not show

- Disk speed on the 256 MiB to 2 GiB runs: those files were in RAM. Only the 50 GiB run reads from a disk, a SATA SSD; an NVMe drive or a spinning disk would give other times.
- A cold start: no run on this page began with the page cache dropped.
- Other tools than GNU `diff` and `git diff`.
- A run above 50 GiB.
- Different machines side by side. Compare the memory between the tables, not the times.
